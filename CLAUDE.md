# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`metro` is a Unity rhythm-game prototype: four lanes (L / R on top, ZL / ZR on the bottom) carrying button notes and stick-flick notes, plus two analog-stick lasers flying through the space between the rows, judged against the audio DSP clock.

- Unity **6000.3.10f1**, URP 17.3, uGUI 2.0. Menus and most UI use legacy `UnityEngine.UI.Text`; only the in-song HUD sign prefab uses TextMeshPro (TMP Essential Resources are in `Assets/TextMesh Pro/`).
- **New Input System only** (`activeInputHandler: 1`). `UnityEngine.Input` throws at runtime; read devices via `Gamepad.current` / `Keyboard.current`. `Assets/InputSystem_Actions.inputactions` is the unused template asset — gameplay code polls devices directly.
- All gameplay scripts live in the default `Assembly-CSharp` (no `.asmdef` files, no namespaces).

## Working with the project

There is no build script, CI, lint config, or test suite. `com.unity.test-framework` is installed but no tests exist; adding tests means creating a test assembly (`.asmdef`) first, and since gameplay code has no asmdef of its own, it would need one too before a test assembly can reference it.

Everything runs through the Unity Editor:

- The only scene in the build is `Assets/Scenes/Game.unity`. Open it and press Play.
- The Editor is driven with the official **Unity CLI** (`unity`, installed at `%LOCALAPPDATA%\Unity\bin`) through the `com.unity.pipeline` package — there is no MCP server. It only works while the Editor is open on this project; `unity status` shows connected Editors, and `unity open .` launches one (takes a minute or so). If no Editor is connected, C# changes cannot be compile-checked.
  - Editor commands run as `unity command --project-path . "<group> <name>" [--param value]`. The command name is one quoted argument, and CLI options (`--project-path`, `--timeout`, global `--json`) must come *before* it — anything after it is forwarded to the Editor command as a parameter. `unity list --project-path .` lists every command; add `--json` for parameter details.
  - Compile check: `"script recompile"`, then `"console status"` (`groundTruth.compilationFailed` / `compiling`) and `"console get" --level error --tail 20`.
  - Play mode: `"editor.playmode start" --run-in-background true` / `"editor.playmode stop"`.
  - Screenshots: `"capture game_view" --output-path <png>` (also `capture scene_view`).
  - Driving the menus: `"runtime simulate_key"` did not reach the polled `Keyboard.current` here (a `press` is down+up in one frame; `down`/`up` separately also had no effect). Call the same `GameFlow` methods the inputs call instead, with `"script eval" --code "var f = UnityEngine.Object.FindFirstObjectByType<GameFlow>(); f.LeaveTitle(); return f.CurrentState.ToString();"` (then `OpenGenre(SongGenre.Default)`, `ConfirmSong(index, "01")`, `DepartSong()`, `QuitToSongSelect()`…). Each CLI call takes most of a second, so the door transition (~1.8 s) is usually over before the next capture.
- `Assets/Screenshots/` holds verification captures of the stage layout and the menus (`v3-*` are the station-sign menus, `v7-*` the former station-passage stage, `v8-*` the plain black lanes and the HUD sign as sketched, `v9-*` the backlit HUD sign prefab, `v11-editor3d-*` the chart editor's 3D edit view, `v12-song-intro-*` the "まもなく" screen before a song, `v13-title-*` the route-map title and its mode select). The passage version of `RhythmStageView` / `RhythmJudgementUI`, `StageTextures` and the scene are kept outside `Assets` in `Backups/2026-11-22-station-passage/`.

Unity specifics that matter when editing files directly:

- Every asset has a sibling `.meta` holding its GUID. Move/rename the `.meta` together with the asset, and never regenerate one for an existing asset — scene references (e.g. `Game.unity` → script GUIDs, `demo_chart.json`) break silently.
- `Library/`, `Logs/`, `UserSettings/` are generated; do not edit or rely on them.
- `.git/` is currently an empty directory (not an initialized repository) and there is no `.gitignore`. If git is set up, add a Unity `.gitignore` before the first commit.

Template leftovers unrelated to the game: `Assets/Scenes/SampleScene.unity`, `Assets/TutorialInfo/`, `Assets/Readme.asset`, `Assets/_Recovery/`.

## Architecture

All runtime components sit on one `GameSystems` GameObject in `Game.unity`. Cross-references are serialized where set and otherwise resolved with `FindFirstObjectByType` in `Start`/`Awake`.

```
ChartLoader ──chart──▶ NoteSpawner ◀──consume── JudgeSystem ──events──▶ RhythmJudgementUI / ScoreUI
                          ▲    │                     ▲
SongClock ──SongTime──────┘    └─positions─▶ RhythmStageView (static geometry)
      └────────────SongTime──────────────────┘
```

- **`SongClock`** (`Scripts/Core`) — the single time source. `SongTime = AudioSettings.dspTime - dspStartTime`, with audio started via `PlayScheduled`. All spawning, movement and judgement use this `double`; never use `Time.time`/`deltaTime` for anything gameplay-timed. The scene currently has no `AudioSource` assigned, so the clock runs silently.
- **`ChartLoader`** (`Scripts/Core`) — parses a `TextAsset` with `JsonUtility` in `Awake`, sorts notes/lasers by time, sorts each laser's points, and drops lasers with fewer than two points. Also defines the chart data types (`SongChartData`, `TapNoteData`, `LaserNoteData`, `LaserPointData`, `NoteDirection`).
- **`StickInput`** (`Scripts/Core`) — static, the only place the sticks are read. `Read(side)` returns the stick clamped to the unit circle (arrow keys for both sides when no gamepad is connected); `GetDirection` turns a stick position into a `NoteDirection`.
- **`NoteSpawner`** (`Scripts/Gameplay`) — owns the live note lists. Spawns each note `travelTimeSeconds` before its target time, tells every `NoteView` its `progress` each frame, and feeds stick input into active lasers. It exposes the `TryConsume*` methods, which are the only way notes leave play (they remove from the list and `Destroy` the object).
- **`NoteView`** / **`LaserNoteView`** (`Scripts/Gameplay`) — one live note each. `NoteView.UpdateView(progress, tailProgress)` places the rounded bar on its lane (a box between two cylinders, sized directly each frame so the ends stay round — the root is never scaled), for a directional note the camera-facing chevron, and for a hold the tail bar and body (the chevron, tail and body are siblings it destroys in `OnDestroy`). `LaserNoteView` holds the laser's timed points, draws the not-yet-arrived part as three ribbon meshes cut lengthwise into columns with a cross profile, so it reads as a round glowing tube (a soft outer glow, a band shaded like a cylinder — bright middle, darker soft rims — and a paler HDR core line that blooms) that show stronger while the laser is followed and fade (opacity, not darkening) while it is not, and run a depth gradient along the path (far end dark, faint and hue-shifted toward violet, middle the stick's colour, near end pale and solid), plus a compact **rounded-square** marker (soft halo, feathered ring and inner square; pulse and outward ripples while followed) at its current point on the judgement plane with an **arrow badge** beside it (notched arrowhead with a black outline on a dark round plate with a stick-colour rim) pointing the way the laser turns next (`TryGetNextTurn`: the first later move more than 15° off the current direction, or the first move while it holds still / has not begun; it brightens and nudges outward as the turn nears), and accumulates the followed time. It listens to `GameSettings.Changed`, so a LASER COLOR change recolours lasers already in play.
- **`JudgeSystem`** (`Scripts/Gameplay`) — polls lane buttons (pressed / held) and stick flicks, asks `NoteSpawner` to consume the closest matching note, sweeps expired notes as misses, and judges finished lasers. Holds the timing windows as `const` and reports through the `JudgementResolved` / `LaserJudgementResolved` events. It keeps no score state.
- **`RhythmStageView`** (`Scripts/Presentation`) — `[ExecuteAlways]`: builds the entire 3D stage from its serialized `StageLayout` (camera, depth, lane size, laser space, colours) in `OnEnable`, in edit mode too, and overrides the main camera's transform/FOV and projection: `topInset` (0.15) reserves that share of the screen at the top for the HUD bar, and `ApplyProjection` sets an off-centre projection (`projectionMatrix`, `m12` shift) that fits the whole stage into the region below it — re-applied whenever the view's aspect changes, reset in `OnDisable`. The generated `RhythmStage_3D` objects are `DontSave | NotEditable` previews, rebuilt whenever a layout value changes (also during Play) — tune the stage via the Inspector values, not the objects. The stage is plain for now: black lane surfaces (`leftLaneColor` / `rightLaneColor`) with grey divider and outer edge lines (`boundaryColor`), a glowing white judgement line strip across each lane at progress 1 (`judgementLineColor` × `judgementLineGlow`, `judgementLineWidth`), a black background (`backgroundColor`, to be decided later) and nothing around the lanes. The lanes run on past the judgement line toward the camera (`nearExtension`) and fade into linear fog in the background colour (`RenderSettings.fog`, set here, also in edit mode — `fogStart` / `fogEnd`) at the far end. Surfaces are divided along `CorridorDepth` (the depth of the straight corridor the narrowing tunnel looks like on screen), so `CreateSurface` spaces its rows evenly in 1 / depth. Its volume: bloom from a threshold just under white (0.9, gamma; intensity 0.8, scatter 0.6 in `StageLayout`) so notes, the judgement line, lasers and the HUD sign's white lettering glow, no tonemapping (white stays white), a light vignette; film grain, chromatic aberration and contrast are in `StageLayout` "Post-processing" but 0 by default. When the HUD's overlay camera is stacked on the main camera, that camera post-processes the whole stack and the main camera's own post-processing is turned off (`ConfigureCamera`), so nothing blooms twice. The far end (奥) is the panel in the centre of that region and everything travels outward to the near end (前): the L / R lanes form the ceiling of a tunnel running to the top edge, the ZL / ZR lanes its floor running to the bottom edge, with no gap between the two lanes of a row. The open space between the rows is the laser space, with only four faint rails for depth: lasers are followed by direction, so there is no stick cursor or aim reticle. `backLaneY` (0.3) sets how far the vanishing point looks: smaller = deeper (the far end shrinks toward a point). The APPROACH option (`GameSettings.ApproachAccelerate`, LINEAR / ACCEL, default LINEAR) runs every time-linear progress (notes in `NoteSpawner.GetProgress`, laser points, `TunnelGridView` frames) through `ApplyApproachCurve`: ACCEL draws `progress = linear^k` with k = 1 + 0.2 × ACCEL LEVEL (`GameSettings.ApproachStrength`, 1–10, default 6 = 2.2) and makes `NoteSpawner.TravelTimeSeconds` k times longer (`ApproachTimeScale`), so the notes crawl in from far away and the speed at the judgement line equals LINEAR's (k / (kT) = 1 / T); the hit timing is the same. Any new code that turns a time into a progress must use `ApplyApproachCurve` and `TravelTimeSeconds`. Its static `GetLaneWorldPosition` / `GetLaneWidth` / `GetLaneRotation` / `GetLaneInward` / `GetLaserWorldPosition` / `GetDepthScale` are the source of truth for where things are at a given `progress` (0 = far, 1 = judgement line); `NoteView`, `LaserNoteView` and the HUD labels call them, so stage geometry constants and note motion stay in sync only through these functions. It also owns `CreateMaterial` / `CreateTransparentMaterial` and the stick colours (`GetStickColor`).
- **`TunnelGridView`** (`Scripts/Presentation`) — rectangular frames around the tunnel cross-section (ceiling lane edges, the open sides, floor lane edges; `RhythmStageView.GetTunnelCorners`) that flow toward the player with the notes, for a sense of space. One sits every GRID option beats (`GameSettings.GridBeats`: OFF, 1/4, 1/2, 1, 2, 4; default 1) of the chart's `bpm`, placed at the progress a note at that song time would have (uses `NoteSpawner.TravelTimeSeconds`, so HI-SPEED applies); they fade in at the far end. Colour and width are `gridColor` / `gridLineWidth` in `StageLayout`. It is a component on `GameSystems`, pooled `LineRenderer`s, play mode only.
- **`RhythmJudgementUI`** (`Scripts/Presentation`) — the in-song HUD (`RhythmHUD` canvas): instantiates the HUD sign prefab (`MetroSignHud`, below) from `Resources/UI/MetroSign` and feeds it (song, score from `ScoreTracker`, progress, player name and options), and builds the lane names (white code boxes) and the message popup (READY, in a small dark sign over the far end). There is no on-screen pause button (Esc / Start pause), no judgement counts in the song (the result shows them) and no judgement popup. The canvas is `ScreenSpaceCamera` on a `HudCamera` overlay camera (UI layer only) stacked on the main camera, so the stage's bloom reaches the sign; overlay canvases (`MetroMenus`, `MetroDoors`) still draw above it. `GameFlow` passes the genre letter and station number to `BeginSong`. The lane labels and the message are placed in `BeginSong` (after the stage has placed the camera) by projecting stage positions with `WorldToViewportPoint`, since the stage is not centred on screen.
- **`MetroSignHud`** (`Scripts/UI`, prefab `Assets/Resources/UI/MetroSign.prefab`) — the HUD sign, modelled on a backlit overhead subway guide sign, laid out after the hand-drawn sketch: thumbnail (the chart's `jacket`, or the song's station badge on a white tile; unlit) with title / artist and the level as a line badge in the difficulty colour with a blooming white face | the score (achievement rate to four decimals, the song's progress lit under it) | a user badge (person icon) in a lit difficulty-colour ring with the player name and options | a lit yellow panel with square corners and a black arrow. The sections are split by thick lit white rules with a soft halo. Lit spots: level badge, user ring, both rules, score digits and progress, the yellow panel; the large lettering (title, score, player name) blooms through the Bright TMP material, the rest keeps a faint glow. Layer groups bottom to top: `1_Housing` (black frame, drop shadow, inner-edge highlight), `2_Face` (#05080F→#0B1220 gradient, inner shadow), `3_Rules`, `4_Song`, `5_Score`, `6_Player`, `7_ArrowPanel`, `8_Glass` (white 8 %→0 % diagonal from the top left, a weak reflection). Every layer is a uGUI `Image` with a generated sprite (`Assets/UI/MetroSign/Sprites`); each lit one has a **`SignEmission`** (`IMaterialModifier` multiplying an HDR colour into the UI material's `_Color`, so it can pass the bloom threshold). The lettering is TMP with dynamic OS font assets (Segoe UI Semibold + Yu Gothic UI Bold fallback, not bundled; `Assets/UI/MetroSign/Fonts`) and material presets with HDR face colour and outer glow (`Assets/UI/MetroSign/Materials`, Glow Outer 0.4). The prefab is generated by **Metro > Build HUD Sign Prefab** (`MetroSignPrefabBuilder`, `Scripts/Editor`): it regenerates the sprites and **overwrites the prefab** (Inspector edits to it are lost), but keeps existing fonts and materials. Tune the prefab and the materials in the Inspector; change the builder only for structural changes. White overlays over the dark face need much lower alpha than their gamma-space value (linear blending; the builder's `Overlay()` converts, so the glass's "8 %" is about 1.2 % in the Inspector).
- **`LaneComboView`** / **`LaneJudgementView`** (`Scripts/Presentation`) — world-space canvases lying flat on the lanes, so notes pass over them. The combo is drawn once per row on the divider at progress 0.6 (white at low opacity, "COMBO" in the line colour); each judgement on its own lane at progress 0.85 (`UiKit` judgement colours, FAST / SLOW and ms under it), a laser's on the floor lane of its stick. Both are added by `GameFlow` (`GetOrAdd`) and shown only while a song is on screen.
- **`LaserWarningUI`** (`Scripts/Presentation`, plain class built into the HUD canvas by `RhythmJudgementUI`, which calls `Tick` every frame): a blinking notice at the left and right screen edges (below the HUD sign, `RhythmStageView.TopInset`) that a laser is about to start — left edge for the left stick's lasers, right edge for the right's, in `RhythmStageView.GetStickColor`. Each edge is an `EdgeGlowGraphic` (solid at the screen edge, fading inward), a solid strip and three inward chevrons, all with `SignEmission` so they bloom. It reads `NoteSpawner.Chart` (so mirror and editor previews are right), blinks from `WarningSeconds` (2 s) before a laser's `StartTime`, faster as it nears, and goes out when the laser begins.
- **`ScoreUI`** (`Scripts/UI`) — an older inspector-wired score display with the same scoring logic. It is in the scene but its `Text` references are unassigned, so it is inert.
- **`GameFlow`** (`Scripts/Gameplay`) — the screen state machine and the only thing that starts a song: `Title` (its mode select: ソロ / エディター, or `E`) →(train doors)→ `GenreSelect` (`ChartEditor` opens at once, no doors) →(badge flight)→ `SongSelect` → `SongConfirm` →(doors)→ `SongIntro` (3 s, `songIntroSeconds`) → `Playing` / `Paused` / `Resuming` → `Result`; pause/result "SONG SELECT" goes back through the doors to the same line and song (an editor preview returns to the editor at once). It builds the `MetroMenus` canvas (sort 200: every menu screen, options, pause, result) and `MetroDoors` (sort 500, above the HUD). `IsBusy` (a transition running or the options open) blocks menu input; every screen checks it and `CurrentState` before acting.

### Menus (`Scripts/UI`)

The out-of-song screens follow the hand-drawn design: Japanese station signage. Everything is built in code at the 1920 × 1080 reference (no sprites): `SignKit` holds the palette (off-white face, black ink, steel frame, `MetroRed`), the sign font (Segoe UI with Yu Gothic UI behind it for Japanese) and the builders; the shapes are mesh `Graphic`s — `CircleGraphic` (disc / ring / arcs), `RoundedRectGraphic` (with vertical gradient), `ChevronGraphic`, `HatchGraphic` — sharing `UiMesh`'s 1-unit alpha fringe for anti-aliasing. `LineBadge` is the subway line badge used everywhere (ring 17.5 % of the diameter, letter above / two-digit number below, optional halo); its proportions come from real platform signs.

- **Light / dark theme:** the THEME option (`GameSettings.DarkMode`, last row of the options, also in the pause menu; default LIGHT) switches every menu screen between black on off-white and light on black, the train doors included (the in-song stage and HUD are dark either way). `SignKit`'s palette members (`Face`, `Ink`, `OnInk` = lettering on an ink fill, `Plate`, `Floor`, …) are properties that follow it, `SignKit.Themed(light, dark)` makes more, and `DarkInk` stays black for lettering on light line colours. Use these instead of `Color.white` / literal greys on a sign, and never cache them in a static field. Colours are taken when a screen is built, so `GameFlow.RebuildMenus` (from `LateUpdate`) destroys and rebuilds `MetroMenus` / `MetroDoors` on a change and restores the current screen, the options and the selected row; a screen or state that gains a way to change the theme has to be handled there. In linear colour space translucent light-on-black reads much stronger than dark-on-white, so such overlays take a far lower alpha in dark, and very dark greys should have equal channels (8-bit vertex colours tint them otherwise). `v14-dark-*` in `Assets/Screenshots/` are the dark screens.
- `TitleLogo` (plain class, built by `TitleScreenUI`) — the logo, from the user's SVG (viewBox 600 × 270, scaled 1.6): three stacked bars narrowing downward in route-map colours (`TitleBackdrop.Red` / `Amber` / `Teal`), "metro" spread to a fixed length (one legacy `Text` per letter, gaps from the measured advances, since `Text` has no letter spacing) in `SignKit.TitleFont` (Outfit ExtraLight from `Resources/Fonts/Outfit-ExtraLight` if present, else Segoe UI Light), and a thin wave (`RouteLineGraphic`, a 1¼-period sine) that travels left to right, one wavelength per 6 s, its crest always below the letters, and steps through the six route-map line colours every 7 s (`ColorSeconds`, 1 s cross-fade). `v15-logo-*` in `Assets/Screenshots/`; `v16-settings-*` are the settings screen.
- `TitleScreenUI` — after the hand-drawn sketch: the logo (`TitleLogo`) and "Ⓐ Button" in the middle of the off-white board (same as the song select), over a moving route map (`TitleBackdrop`, a plain class): thick lines with rounded 45° bends (`RouteLineGraphic`, a polyline drawn only between two distances along it) grow in from one edge, stay a while with their stations (rings with "01 –" numbers, popping in as the line reaches them), then run off through the other edge; arrows glide straight across at constant speed above / below / beside the title; small diamonds, dots and rings drift (faded near the title) over a faint dot grid (`DotGridGraphic`). Each of the seven line slots keeps to its own part of the screen with three hand-made paths (`CreateSlots`, centre units of the 1920 × 1080 reference, all clear of the `KeepOut` rect around the title) and draws path, mirroring, direction, colour (six: ink, grey, red, orange, amber, teal), width, speed and stations from a fixed-seed `System.Random`, so the show is the same every launch and restarts from empty on `Show`. Confirm / click sweeps every line off along its path, lifts "metro" to the top and grows in the mode select (`TitleModeSelect`, from the second sketch): a chevron and a notched route arrow band (`PolygonGraphic`) in the chosen mode's colour carrying boxes 1 ソロ / 2 マルチ / 3 エディター (← → / 1–3 / mouse; マルチ is not made yet and refuses with a shake and a notice). ソロ → `LeaveTitle`, エディター → `OpenChartEditor`, Back → the title again. Coming back from the genre select or the chart editor opens the mode select directly (`ShowModes`). `HatchGraphic` is currently unused.
- `TitleQuitDialog` — quitting: the "終了" plate in the title's bottom right corner (not on the mode select) or Esc / B on the title opens a confirmation (いいえ chosen first); `Application.Quit`, or leaving Play mode in the Editor.
- `TrainDoorTransition` — zooms out from an open doorway to a train car side (side window, double doors, door lamp, line stripe), closes the doors, runs the caller's `onClosed` (swap screens there) while the station badge flips to the next number, opens the doors and zooms through.
- `GenreSelectUI` — full-screen sign like a transfer-station board: "Genre" and one badge per `SongGenre` with its English name (this screen is English only; number = song count; empty genres are grey and refuse with a message). The song select header still shows the Japanese genre name too.
- `SongSelectUI` — the genre's line as a route map: stations (songs) down a vertical line that curves off to the top left (`GetPathPoint` places stations along straight → bend → diagonal), the selected one large with title / artist / info beside it and its number as a faint watermark. Colours come from difficulty, not genre: each station badge has its own song's `SongDifficulty` colour, and the line, bend and header badge ease to the selected song's colour; above the title sits the difficulty row — one pill per grade (LOCAL / RAPID / EXPRESS / LIMITED EXPRESS) with the song's level in it, greyed where the song has no chart. A station is a *song*, not a chart: charts with the same title and artist in a genre are that song's difficulties (`ChartLoader.GetSongGroups`; station numbers and song counts use `GetSongCount`). Left / right (stick, d-pad, arrows) step through them: the filled cursor slides to the new pill and changes colour, the station badge flips over to the new colour, the title block swipes in from that side; past either end the row shakes and that side's chevron flashes red. Moving up / down keeps the chosen grade (or the nearest one the song has).
- `SongSignUI` — the selected song as a platform station sign over the dimmed route map: title, artist, stats, then the line band (difficulty colour) with the level badge, two chevrons and a spinning start circle; best score bottom left. The train doors' line colour is the browsed song's difficulty colour too (`GameFlow.GetBrowsedLineColor`).
- `SongIntroUI` — after the sign's start, behind the doors and held `GameFlow.songIntroSeconds` (3 s) once they open: the display above a car's door announcing the next stop, after the hand-drawn sketch — the service box (the chart's difficulty as 各停 / 快速 / 急行 / 特急, `SongDifficulty.JapaneseName`, with the English name and level) top left, artist and, large, "まもなく / Soon" and the title, "metro" with the M badge top right, a rule in the difficulty colour, the cover art (`jacket`, or the station badge on a white tile) in the middle, and a bottom rule that fills over the hold. The song starts under it and it fades out over the stage. Retry and editor previews skip it.
- `SettingsScreenUI` — the settings, full screen (after the hand-drawn sketch): five tabs drawn as 3D boxes standing on a line in the song in view's line colour (ゲームプレイ / オーディオ / グラフィック / 入力 / その他; the chosen one larger and filled with the line colour), and under them the tab's settings as cards in a 3 × 3 grid (filled column by column): a name plate over a value box with ◁ ▷ small steps and ◁◁ ▷▷ large steps, the amounts written under them (速度 ±0.1 / ±0.5). Opened by `SettingsButton` (a gear in a box the shape and size of the screens' "M00" code box, mirrored to the top left, not animated, on the genre select, song select, sign and pause — not the title / mode select, the result, the chart editor or in the song; `GameFlow.LateUpdate` shows it) or Tab / Y; its own "× 閉じる" plate sits in the same place. Keys: Q / E or LB / RB switch tabs (also ← → after ↑ from the first card), ↑ ↓ select, ← → step, Shift + ← → or LT / RT the large step, Esc / B / Tab close. The input tab shows the controls beside its card; その他 has PLAYER NAME (opens `NameEntryUI` on top) and THEME. The audio tab also has NOTE SOUND (default off) and its volume: `NoteSoundPlayer` ticks on every non-Miss button / flick judgement. Its MASTER / MUSIC VOLUME and AUDIO OFFSET are `GameSettings` options applied by `GameFlow` (`AudioListener.volume`, `SongClock.SetMusicVolume`, added to the chart's `audioOffset` when a song starts). `OptionsOverlayUI` / `OptionsMenu` are no longer used.
- **Timing adjustment:** three offsets in `GameSettings`. JUDGE OFFSET (`JudgeOffsetMs`, ±200) is subtracted from the time of button / flick / hold input (not lasers). DISPLAY OFFSET (`VisualOffsetMs`, ±200, positive = drawn later) moves only what is seen: notes and lasers (`NoteSpawner`'s `viewTime`), `TunnelGridView` and the laser warnings; new code that draws something against the song clock must subtract it, judging code must not. AUDIO OFFSET shifts the music. `TimingCalibrationUI` (the タイミング調整 card on the settings' gameplay tab) measures the first two by tapping along: clicks only (shifted by the audio offset) → judge offset = median tap error; falling note only → display offset = judge offset − median tap error (so sound first, then picture). It times taps on the DSP clock per frame, like the game.
- `NameEntryUI` — player name entry (`GameSettings.PlayerName`, up to 16 characters, PlayerPrefs; empty = "PLAYER"): typed on the keyboard through `Keyboard.onTextInput` with the IME enabled while open (the composition shows grey), or picked from a key grid (A–Z, a–z, 0–9, `- _ .`, SPACE / DEL / CANCEL / OK) with arrows / stick / d-pad and A, or the mouse. It polls the devices itself, not `MenuInput`, because `MenuInput` maps W / A / S / D, Space and Backspace to menu actions; the options board behind ignores input while it is open.
- The in-song screens use the same signage: pause (`PauseMenuUI`) and result (`ResultUI`) are sign boards over `SignKit.Dim` with the song's badge as the station name and its line band (the result's rank sits on the band in a large badge, like the level on `SongSignUI`); the resume countdown is a `LineBadge`. Their rows are `MenuList` in `MenuList.Look.Sign` (selected row inked black with a line-colour marker; `MenuList.LineColor`). On the off-white face, judgement colours come from `SignKit.GetJudgementColor` (the pastel `UiKit` ones are for the dark stage: the on-lane judgements, FAST / SLOW). The stage and the in-song HUD sign are dark (see `RhythmStageView`, `RhythmJudgementUI`); the pause / result boards stay off-white.
- Gotchas: legacy `Text` centres the font's whole line box, so capitals sit ~0.19 em below the middle of their rect — raise centred text by `fontSize * SignKit.CapRaise`. The project renders in linear colour space, so a translucent dark panel over the white signs looks much lighter than its alpha suggests (the sign's dim is 0.93, the options backdrop 0.95).

### Chart editor (`Scripts/ChartEditor`, title screen > CHART EDITOR / `E`)

An IMGUI screen of the game itself (`ChartEditorScreen`, a MonoBehaviour on `GameSystems` that `GameFlow` enables in `State.ChartEditor`; it draws in `OnGUI` over everything) that edits the JSON files in the chart folder on a vertical timeline (time runs upward). The folder (`ChartLoader.UserChartsDirectory`) is `Assets/Resources/Charts` in the Editor and `persistentDataPath/Charts` in a build; the game library reads Resources, plus that folder in a build, and `CloseChartEditor` reloads it. Columns are ordered by hand: left-stick laser X / Y, lanes L / R / ZL / ZR, right-stick laser X / Y. Notes snap to a beat grid built from the chart's `bpm` and `offset`: the grid is one beat cut into N parts (control bar グリッド ◀ ▶ steps the presets 1 / 2 / 3 / 4 / 6 / 8 / 12 / 16, 分割 types any 1–64; `[` `]` too), 吸着 (`G`) turns snapping off, Alt skips it while held; beat lines are numbered 1–4 in the ruler and measure lines `#n`. **Tools** (left tool strip, or keys): `V` 選択 (click selects, drag moves, drag on an empty spot box-selects), `B` 範囲選択 (box select from anywhere), `N` ノーツ (the all-round placer: click an empty spot = place a note; dragging out of it gives it a direction, 8-way by drag angle, 14 px threshold, `DragMode.SetDirection`; Ctrl+drag up makes a hold; dragging a note moves it), `H` ロング (drag up = a hold; dragging a note stretches it), `F` フリック (drag = a flick-only note with that direction; a plain click uses the direction set in the control bar), `L` レーザー (the only tool that places laser points in the laser columns: click adds a point to the selected laser, Shift+click starts a new one), `E` 消しゴム (click or drag over notes / laser points). In every tool **right-drag** places / turns a note into a flick-only one (a plain right-click deletes, decided on release), Shift+drag on a note sets its direction, and dragging a hold's tail resizes it. The screen was ported from a UnityEditor window, so it keeps the `EditorGUILayout` / `Undo` / `Handles` names through runtime shims in `EditorGuiShim.cs` (namespace `MetroEd`, text fields parse numbers while typing, `Popup` opens inline). `Handles` lines are GL quads in screen pixels, clipped by hand at `Handles.SetClip` — IMGUI clips a rotated texture as if it were unrotated, which is why the old rotated-rectangle lines spilled out of the timeline or vanished near its right edge.

**Layout** (`ChartEditorLayout.cs`, a partial of `ChartEditorScreen`), like a drawing app: menu bar (ファイル / 編集 / ツール / 譜面 / 表示 / 再生 / ウィンドウ / ヘルプ, the chart name opening the chart list, transport, and the 2D / 3D sidebar toggles at the right) | control bar (grid, snap, zoom, then the selection's properties — lane, time, hold, flick-only, stick, direction row, laser point time / X / Y — or the current tool's placement settings) | tool strip | timeline | 2D preview sidebar | game preview sidebar (3D) | status bar (time, tool, selection, hint / tooltip). Both sidebars are toggled independently (menu bar buttons, ウィンドウ menu, Ctrl+1 / Ctrl+2) and resized by dragging their left edge; visibility, widths and the tool persist in PlayerPrefs (`ChartEditor.*`). Chart info (title … audio, stats), playback settings (volumes, return on stop, auto play) and the key list are floating dialogs from the menus (`I`, F1). The **laser 2D views** (Ctrl+3) sit at the bottom of the laser columns, one per stick: the selected laser's whole path with numbered, draggable points, the lasers of the coming measure fading out, and where the stick is at the playhead; with the laser tool a click there puts a point at the playhead (a new laser when none is selected). The playhead is kept above them (`FollowCursor` / `PlayheadLift`). IMGUI gotchas handled there: floating parts (menus, chart list, dialogs) are drawn last but `HandleOverlayInput` takes their clicks first and the base screen is disabled for a click on them (`pointerBlocked`); anything that adds or removes GUILayout controls (tool, selection-dependent controls, sidebars, keyboard shortcuts, menu commands) runs through `Defer` at the next Layout event.

- The chart being edited lives in `ChartEditorDocument` (a hidden ScriptableObject). Edits go through `Modify` / `DragModify`; `MetroEd.Undo` is a whole-chart JSON snapshot stack (a drag is one step; Ctrl+Z / Y); undo/redo clears the selection.
- `ChartJsonWriter` saves in the hand-written compact layout (one note per line, default-valued fields left out), so saved charts stay diffable. It is the only writer — do not save with `JsonUtility.ToJson`.
- Files: ファイル menu (新規 Ctrl+N / 開く… Ctrl+O / 譜面一覧 / 保存 Ctrl+S / 書き出し… to save a copy anywhere; 保存 never asks where, it writes into the chart folder, giving a new chart or one opened from elsewhere a free file name) and the chart list under the chart name in the menu bar. `NativeDialogs` uses the Windows common dialogs and message boxes (P/Invoke, blocking); elsewhere they do nothing.
- `ChartEditorPlayback` plays the music with a clap on every note (ノーツ音) and an optional metronome on the beats of `bpm` / `offset`, higher on each measure's first beat (menu bar toggles ノーツ音 / メトロノーム, `T`; volumes in 再生設定; persisted as `ChartEditor.*`). The sidebar game preview sounds both through `Follow`; the full-screen preview does not. Its clock is the wall clock re-synced to the music's sample position. Play starts from the cursor (Space), from the start (再生 menu), or from a measure number typed in the menu bar (小節 / 移動); "return on stop" puts the cursor back where the playback began.
- The 2D preview sidebar draws the chart as the player sees it (notes falling to a judgement line, two stick pads with the laser paths) at the playhead, so it follows playback and shows the notes ahead of the cursor while stopped.
- A timeline box selection is anchored to a song time (`boxStartTime`), so it keeps its start while the wheel or the edge auto-scroll (`AutoScrollBoxSelect`) moves the view. The 3D view's box is still a screen rectangle.
- **Selection, mirror, reverse:** a selection is notes plus whole lasers (`selectedNotes` + `selectedLasers`; box select takes a laser when any of its points is in the box, Ctrl+click on a laser adds it); `selectedLaser` / `selectedPoint` is the single laser being shaped, and a selection of one laser alone collapses into it (`FinishSelectionOfLasers`). Copy / delete / paste cover both. `MirrorSelection(horizontal, vertical)`: 左右 (M) L↔R, ZL↔ZR, laser side swapped and X negated; 上下 (Shift+M) L↔ZL, R↔ZR, laser Y negated; 上下左右 (Ctrl+M) both (L↔ZR, R↔ZL). Directions, explicit sticks and spins follow (a single reflection reverses a spin). 前後反転 (`ReverseSelectionInTime`) plays the selection backwards; 選択範囲を反転 (Ctrl+I, `InvertSelection`) selects everything else. Buttons for these are in the control bar for any selection.
- **3D edit view** (`ChartEditor3D.cs`, Tab or the 2D ⇄ 3D switch in the menu bar; persisted as `ChartEditor.EditView3D`): replaces the timeline with the chart inside a straight box running along time (no narrowing, unlike the game): ceiling = L / R, floor = ZL / ZR, lasers between (x / y × `Laser3DHalfWidth` / `Laser3DHalfHeight`), z = time × `DepthPerSecond` (= the timeline zoom / 60, so Ctrl+wheel stretches it). The red frame is the playhead and its cross-section the placement plane: the laser tool puts points on the work plane (side from the control bar's 新しいレーザー 左 / 右, or the selected laser's). Points move like in CAD (`ChartEditor3DGizmo.cs`): a gizmo on the selected points / whole lasers (not with notes selected) has X / Y / depth (time) arrows and XY / XZ / YZ squares; dragging a point itself or placing one uses the work plane (toolbar 作業面: 自動 = the plane the camera faces most, XY = the playhead cross-section, XZ / YZ = running along time at the selected point's Y / X; persisted as `ChartEditor.WorkPlane3D`), Ctrl-drag = time only. Moves keep the timeline's rules (`Snap`, `SnapLaserValue`, Alt skips, -1..1, a point never passes an unmoved neighbour). Lane clicks go through the same `OnLaneMouseDown(event, lane, mouse, time, hit, tailHit)` as the timeline, so every tool behaves the same. Camera like a CAD viewer orbiting a target that follows the playhead (so playback and the game preview move the view while the game preview sidebar shows the real game): middle drag orbit, Shift+middle pan, Ctrl+middle / Shift+wheel zoom, wheel steps the playhead, presets 正面 / 上 / 横 / 斜め and 平行投影 in its toolbar. It draws with GL (`Hidden/Internal-Colored`) into a RenderTexture shown with `GUI.DrawTexture` — no scene objects, cameras or layers — and picks with the same matrices (`Ray3D`, `Project3D`). Vertex colours go in unconverted (the RT path already comes out right; converting to linear made them too dark).
- **Game preview sidebar** (3D, shown by default): `GameFlow.SetGameViewport` (called every frame by the editor with the sidebar's rect below its header, or the full rect while it is hidden) sets `Camera.main.rect` and the HUD camera's rect through `RhythmJudgementUI.SetViewport`, which also switches the HUD canvas to a constant scale of (part width / 1920) so the sign fits; `RhythmStageView` re-fits its projection to the new aspect by itself. The editor draws nothing over that rect.
- **Playing from the playhead, like a video editor:** the playhead is the cursor (click or drag the ruler; clicking during playback carries on from the new spot, `scrubResume`). `Space` plays the music alone (claps / music toggles); `P` plays the game's preview from there in the game preview sidebar (`GameFlow.StartEmbeddedPreview`: auto play forced and restored, run-up = the notes' travel time, the editor's cursor follows `PreviewSongTime`, ends by itself after the last note, `P` again stops). The two stop each other, and with "return on stop" the playhead goes back to where playback began. With the sidebar hidden `P` is the full-screen preview below. `R` / ⏮ 最初から (menu bar and 再生 menu, `PreviewFromStart`) restarts either preview from time 0.
- **Preview in full screen** (`Shift+P`, or `P` with the game preview hidden): `GameFlow.PreviewFromEditor` plays the chart unmirrored from the cursor, drops everything that starts earlier, and never saves a best score; the pause menu / result "SONG SELECT" returns to the editor at once, without the doors (`previewFromEditor`); Retry replays the preview. `P` also closes it (`GameFlow.ClosePreviewByKey`, on the key's release so the editor does not take the same press as another preview). Typed titles / artists / audio paths drop `<` `>` (`ChartLoader.RemoveTagBrackets`, also applied on load), since the displays read tags like `<br>` as rich text.
- Audio is the chart's `audio` Resources path (text field); waveforms need the clip's Load Type to be *Decompress On Load* (`AudioClip.GetData`).

### Conventions that are easy to miss

- **Everything visual is procedural** except the HUD sign prefab (`MetroSignHud`, generated by its builder, with its sprites / TMP fonts / materials under `Assets/UI/MetroSign`). Otherwise there are no prefabs or material assets; `NoteSpawner` falls back to `CreatePrimitive`/`AddComponent` when its prefab fields are null (which they are), and materials are created at runtime by `RhythmStageView.CreateMaterial` from `Universal Render Pipeline/Unlit` (fallback `Unlit/Color`), setting both `_BaseColor` and `_Color`. Lasers use `CreateTransparentMaterial` (`Sprites/Default`, alpha-blended, no depth write); `CreateTexturedMaterial` takes a texture (unused while the stage is plain). Changing the look means changing code, not assets.
- **Deliberate duplication to keep in sync:** the score table (Perfect 1000 / Great 700 / Good 400, Miss resets combo) is in both `ScoreTracker` and `ScoreUI`; the timing-window and key-mapping text on the HUD is the `TimingWindows` Text in the scene, not derived from the `JudgeSystem` constants.
- **Four lanes.** Chart `lane` 0 = L, 1 = R (upper row), 2 = ZL, 3 = ZR (lower row). ZL sits under L and ZR under R, like the controller; `LowerRowCrossed` in `RhythmStageView` can swap the lower row (the original design sketch drew it crossed). `lane % 2` is the side: it picks the button-held beam colour and the default stick of a directional note (a note's `stick` field can override it).
- **Note colours.** Plain bars are white and hold notes violet (`tapNoteColor` / `holdNoteColor` in `StageLayout`); the bar under a directional note follows the same rule. A button note with another lane's button note at the same time (within 2 ms; flick-only and spin notes do not count) has a yellow bar (`simultaneousNoteColor`, decided in `NoteSpawner.IsSimultaneous`); for a hold only the head bar turns yellow. Everything played with the left stick is cyan-blue and with the right stick magenta: lasers, their markers and next-turn triangles, the chevrons of directional notes and the side warnings. The chevron's colour is what tells the player which stick to use. The options LEFT / RIGHT LASER COLOR (`GameSettings.LeftLaserColorIndex` / `RightLaserColorIndex`, a preset palette; DEFAULT = the `StageLayout` colour) override it through `RhythmStageView.GetStickColor`, so everything above follows (chevrons already in play keep their colour until replaced). The `StageLayout` values are serialized in `Game.unity`, so changing a default in code alone changes nothing in the scene.
- **Layout is tuned for 16:9.** The HUD is the sign along the top; the stage fills the region below it (`topInset`), and the judgements are drawn on the lanes. On regions narrower than 16:9 `ApplyProjection` widens the FOV so the outer lane edges stay on screen.
- **Stick direction matching:** a stick "points toward" a direction when it leans at least 0.5 (`StickInput.TiltThreshold`) and within ±`GameSettings.StickAngleDegrees` of it (option STICK ANGLE, 15–60°, default 30; 22.5 would split the eight directions exactly). `StickInput.PointsToward` is used by both directional notes and lasers.
- **Directional notes** (`direction` ≠ None) have eight directions and are played with the note's stick (`NoteView.Side`: the chart's `stick`, else the lane's side — so an L-lane note can be played with the right stick). The chevron is always taken by **flicking** that stick its way, whether or not it sits on a bar: `NoteSpawner.Spawn` turns a chart note with a bar and a direction into two `NoteView`s at the same time — a plain bar (button, normal windows, may be a hold) and a flick-only chevron — judged independently, so such a note yields two judgements (`SongChartData.AttachedFlickCount` adds them to `JudgementCount`). A flick-only chart note (`flickOnly`) is just the chevron. A flick is the frame the stick starts pointing in a direction (past 0.6 from the centre, or swinging into another 45° sector, kept until it leaves its sector by 10°; it re-arms below 0.35); it takes the closest chevron in each lane if the stick then points toward the chevron's direction and the direction it pointed in before did not already (so a stick merely held that way never takes one). Buttons never take chevrons.
- **Note judgement windows:** buttons ±35 / 70 / 110 / 160 ms (Perfect / Great / Good / consume-or-miss), flicks looser at ±60 / 100 / 150 / 200 ms (`JudgeSystem.Flick*WindowSeconds`). An input only consumes a note inside its last window, beyond Good it resolves as `Miss`; inputs with no matching note in range are ignored.
- **Laser judgement** is by direction, not position (SDVX-style). While the laser crosses the judgement plane, each frame checks whether the side's stick points toward the way the laser is moving (now or within ±0.08 s, `DirectionGraceSeconds`, so corners can be taken slightly early or late); a stretch where it holds still counts as followed with no input. The followed share of the laser's time (time-weighted) is `TrackingAccuracy` (≥0.90 Perfect, ≥0.70 Great, ≥0.45 Good), resolved once when the laser ends. Auto play feeds the laser's movement direction into `StickInput`.
- **Input mapping:** lanes L / R / ZL / ZR = gamepad left shoulder / right shoulder / left trigger / right trigger, or keyboard `D` / `K` / `F` / `J`. Left stick = left laser and directional notes on L / ZL; right stick = right laser and directional notes on R / ZR. The arrow keys drive both sticks at once, but only when no gamepad is connected.

### Chart format

Every JSON TextAsset in `Assets/Resources/Charts/` is a song (`ChartLoader.LoadLibrary`). Because it is parsed with `JsonUtility`, field names must match the C# fields exactly, enums are integers, and missing/extra fields fail silently.

```json
{
  "title": "Flick & Laser Demo",
  "bpm": 120,
  "genre": "pops",
  "notes":  [{ "lane": 0, "time": 1.50 }, { "lane": 1, "time": 2.00, "direction": 3 },
             { "lane": 0, "time": 2.50, "direction": 6, "stick": "R" }, { "lane": 3, "time": 3.00, "direction": 1, "flickOnly": true },
             { "lane": 2, "time": 4.00, "duration": 1.50 }],
  "lasers": [{ "side": 0, "points": [{ "time": 6.0, "x": -1.0, "y": 0.0 }, { "time": 7.0, "x": 1.0, "y": 0.0 }] }]
}
```

Times are seconds on the song clock (not beats; `bpm` and the optional `offset` — seconds of the first beat — only space the scrolling tunnel frames and the chart editor's grid). `audio`: optional AudioClip path under a Resources folder, without extension. `audioOffset`: seconds the music is shifted later on the song clock (negative = earlier; default 0); set by dragging the waveform column in the chart editor or its 波形から開始位置を自動調整 button (first audible spot → the chart's `offset`). `jacket`: optional cover art (表紙) for the HUD, a Texture2D path under a Resources folder without extension (cropped to a square; without it the song's station badge is shown). `genre`: the song select folder — a `SongGenre` id (`"pops"`, `"vocaloid"`, `"game"`, `"original"`) or its letter (P / V / G / M); omitted or unknown = original. The genre table (letters, Japanese / English names, line colours) is `SongGenre.All` in `Scripts/Core/SongGenre.cs`, and a song's station number is its place on its line (library order: level, then title). `difficulty`: 0 Local (green), 1 Rapid (yellow), 2 Express (red), 3 Limited Express (purple); omitted = Local. It only picks the song select / sign / door colour (`SongDifficulty.All` in `Scripts/Core/SongDifficulty.cs`) and is independent of `level`. To give a song several difficulties, make one chart file per difficulty with the same `title` and `artist` (and genre) and a different `difficulty`; each chart keeps its own `id`, so best scores are per difficulty. `lane`: 0 L, 1 R, 2 ZL, 3 ZR. `direction`: 0 or omitted = plain button note, 1 Up, 2 Down, 3 Left, 4 Right, 5 UpLeft, 6 UpRight, 7 DownLeft, 8 DownRight. `stick`: `"L"` / `"R"`, the stick that plays the direction (omitted = the lane's side). `flickOnly`: `true` = direction with no button (ignored without a `direction`). `duration`: seconds the button is held after the hit (0 / omitted = not a hold; ignored on flick-only notes). Mirror mode swaps lanes, left/right in directions and an explicit `stick`. Laser `side`: 0 = left stick, 1 = right stick. A laser moves in a straight line between consecutive `points`; `x` / `y` are stick positions (-1..1, right and up positive) and are clamped to the square -1..1 on each axis (`StickInput.ClampToSquare`), so a point may sit in a corner even though a real stick only reaches the unit circle; the chart editor's stick pads still draw the circle, with a faint square marking the placeable area.
